# UPI Personal Debug Feedback Loop

## Scope

This document records a personal, optional method for using writing and language-production deviations as diagnostic signals during iterative problem solving.

It is not a universal model of dyslexia, language production, cognition, or human behavior.

## Core distinction

A visible form deviation does not automatically imply a semantic or reasoning error.

Potential sources include:

- keyboard/tangent miss;
- spelling/orthographic variation;
- language-production coordination variation;
- dyslexia-related variation;
- combinations of the above.

The method therefore separates form from meaning before interpreting the deviation.

## Feedback loop

```text
intent
  -> expression
  -> interpretation
  -> deviation detected
  -> locate error source
  -> correct
  -> repeat
```

The useful diagnostic object is the difference between:

```text
intended meaning
vs.
written form
vs.
interpreted meaning
```

A correction can therefore improve both sides of a communication loop: the expression and the interpretation.

## Observed examples

Examples such as `för` / `förr`, `väg` / `vägg`, and `höll` / `häll` illustrate that closely related written forms can compete while the intended semantic context remains available.

A second reading can expose a form deviation that was not visible during initial production. In some cases the reader may detect that a form is wrong without immediately being able to produce the correction.

## Intentional omission as a boundary

An omitted explanation should not automatically be treated as a missing step.

In this method, the analyst first checks whether the omission is itself an intentional boundary or scope marker.

This prevents the debugging process from re-explaining a distinction that the original writer already encoded.

## UPI classification

- **OBS:** personal observations and test cases.
- **ERR:** observed output deviations, without assuming their cause.
- **DER:** the feedback-loop structure derived from repeated observations.
- **HYP:** proposed explanations for why a specific deviation occurs.
- **EST:** external scientific findings that independently support relevant mechanisms.
- **SYM:** symbolic representations of the loop.
- **SCOPE:** personal/optional method, not a universal claim.

## Research mapping

Relevant research domains for independent verification include dyslexia and orthographic processing, language production and lexical access, proofreading and error detection, motor/language coordination, and feedback/error-monitoring mechanisms.

Personal observations should remain separated from established research findings. The research layer can test whether parts of the observed pattern generalize beyond the individual.

## Practical use

1. Preserve the original expression.
2. Identify the deviation without assuming its cause.
3. Separate form error from semantic error.
4. Test the interpretation against context.
5. Correct the smallest necessary element.
6. Run the same expression through the loop again.
7. Record recurring mismatches as potential debugging signals.

The goal is not perfect first-pass output. The goal is a system where deviations provide information that can improve the next iteration.

## Boundary

This method is a tool for optional use, especially for personal debugging and communication workflows. It should not be presented as a diagnosis or as a claim that dyslexia functions identically for everyone.
